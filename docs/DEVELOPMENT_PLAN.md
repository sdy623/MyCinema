# MyCinema 制作与自动验证计划

## 发布目标

发布候选必须使用官方固定依赖，保留完整影院功能，并在同一次自动流程中证明源码、运行时、客户端媒体播放、专用服务器持久化与最终 JAR 都符合要求。

## 单一入口

Windows：

```text
gradlew.bat verifyRelease
```

Linux / macOS：

```text
./gradlew verifyRelease
```

该任务按依赖顺序执行以下门槛；任何一步失败都会返回非零状态，不生成“通过”结论。

## Gate A — 源码、模型与界面检查

- 编译 MyCinema 与测试源码；
- 执行电影库、节目、排片、权限、海报、面板、门、座位、音频、镜像、跳转、自动化及网络模型检查；
- 检查中英文界面结构、WaterUI 文档和资源引用；
- 检查 7 个 Ponder 教程的组件清单、独立结构蓝图、英文与中文标题／步骤，并验证生成器输出未漂移；
- 核对 GameTest 类清单必须正好为已审查的 48 个类。

## Gate B — 完整 GameTest 运行

- 在一次性 NeoForge GameTest 世界中运行 48 个测试类；
- 运行时必须发现并完成 241 个用例；
- 禁用、遗漏、跳过、超时或失败均使门槛失败；
- `tools/check_gametest_run.py` 解析实际日志并写入机器可读结果。

## Gate C — 两次启动的专用服务器

第一次启动创建并操作影院，验证设备登记、放映机组、排片开始/结束、授权、保存和正常关闭。第二次启动重新读取同一世界，验证身份、拓扑、历史、授权和排片状态仍然存在，再次完成放映周期并正常关闭。

结果写入 `build/release-evidence/dedicated/`。

## Gate D — 干净客户端与真实电影播放

客户端任务自动创建隔离世界，并在回环地址提供由构建生成的 8 秒 H.264/AAC 测试影片。它验证：

- 官方 WaterFrames、WaterMedia 和 Binaries 的精确版本；
- FFmpeg 初始化、真实视频纹理、硬件解码状态和 OpenAL 音频来源；
- 播放时间推进、暂停稳定、暂停中跳转、停止；
- 两台放映机共享同一影厅显示与服务器时钟；
- `mycinema:cinema_projector` 与 `mycinema:imax_gt_projector` 均已注册并加载各自物品/机柜模型；
- IMAX GT 的 18 个占用格完整、碰撞与美术长方体一致，透明占位格不裁掉下方地板，并生成一张无遮挡机柜截图；
- TMS 自有机柜美术及媒体、放映组、音源原点三页控制都在真实客户端加载并截图；
- Ponder `1.0.87+mc1.21.1` 与其 Flywheel `1.0.4` 运行时加载；7 个 MyCinema 场景全部能从组件索引找到并实际编译；
- 自动打开馆长终端的 Ponder 教程，确认蓝图、文本与物品模型可见，并生成 `mycinema-qa-ponder-manager.png`；
- 五页经理界面、保存、退出、重新进入和继续播放；
- 第一次与最终卸载后 FFmpeg 解码线程均为零；
- 播放、暂停、重连和完成检查点截图齐全。

结果与截图写入 `build/release-evidence/client/`。这条证据明确区别于仅验证数据模型的离线测试。

### 发布前新增工作 — DCP 直接播放

- 把包含 `ASSETMAP` 的完整 DCP 目录作为媒体源，而不是把单个 MXF 或 CPL 当成普通视频文件；首个验收对象使用未加密的 SMPTE / Interop 2K DCP。
- DCP 播放链验证与 IMAX GT 满画幅展示使用不同素材：`Charge` 约为 2.39:1 Scope，只能作为 Scope 播放样片，绝不标为 IMAX GT 画幅。IMAX GT 主截图和满屏演示另用 MyCinema 自制、按 1.43:1 构图的授权素材；不得拉伸、裁掉关键画面或用上下黑边冒充 GT 满画幅。
- 当前固定的官方 WaterMedia 3.0.0 使用 FFmpeg 播放器，因此不把 DCP 支持错误描述成现成功能，也不修改或重新分发 WaterMedia。MyCinema 新增自有的可选 libVLC DCP 播放器，只在识别到 DCP 源时通过固定版本的运行时连接点接管；MP4、网络流和图片继续走官方 WaterMedia。
- libVLC 运行时作为单独声明的可选外部组件取得。启动时检查 DCP access-demux、JPEG 2000、MXF 和 PCM 支持；缺少组件时给出可操作的错误，不静默回退成只播放某个 MXF 文件。
- DCP 播放器读取 AssetMap、PKL 和 CPL，支持多 Reel、暂停、跳转、停止、音量与服务器权威时钟；加密 DCP 只有在用户明确提供有效 KDM 时才尝试载入，首版验收不依赖加密内容。
- 客户端验证必须用完整 DCP 目录真实播放，记录画面纹理、PCM 音频、时钟推进、暂停稳定、跨 Reel、跳转、结束和释放后的线程状态。另保留 VLC 独立播放同一 DCP 的对照结果，并检查 MyCinema 的 MP4/H.264/AAC 路径没有回归。
- DCP 属于客户端解码能力；专用服务器只保存获准的来源标识、节目状态和权威时钟，不读取影院文件，也不要求安装 libVLC。

完成上述实现和真实 DCP 验收后，才把 DCP 写入 README 的已支持格式与 `v0.1.0` 发布说明；在此之前只标记为发布前工作。

## Gate E — 构建与许可合规

- 构建 MyCinema JAR；
- 检查仓库没有第三方或本地依赖 JAR；
- 检查 JAR 没有嵌套依赖和第三方类；
- 核对许可证、NOTICE、第三方说明和固定依赖坐标。

## 发布规则

只有 `verifyRelease` 对同一源码状态完整通过，才可以整理单提交分支和源代码压缩包。测试证据不进入 MyCinema JAR；外部依赖也不进入仓库或压缩包。GitHub 远程发布是独立的最终动作，在仓库内容、说明文字和发布权限确认后再执行。

## 后续里程碑

### 0.2 — 影院音响系统

- 建立 MyCinema 自有的影院音响拓扑，而不是为每个音箱创建独立媒体播放器；整厅继续共享 TMS 的唯一影片时钟与音轨。
- 增加可登记的音响组件：银幕后左／中／右声道、低频效果（LFE）组件、侧环绕、后环绕与顶部声道，并为每件设备保存稳定 ID、所属影厅、位置、朝向和通道用途。
- 提供处理器／功放机架管理页，完成通道映射、静音、测试音、延时、增益和故障状态；所有操作继续执行所有者、距离、加载区块与服务器权限检查。
- 复用现有“放映机中点／银幕中心／观众区中心”音源标定，新增按组件位置验证的声场预览；不把数据检查冒充真人听感或房间声学模拟。
- 保留现有 `mycinema:speaker_collision_core` 世界数据，先在存档副本中设计迁移，再决定是否向玩家提供可制作的实体音响组件。

### 0.3 — 影院音响组件与施工工具

- 提供统一风格的音箱机柜、壁挂／吊装件、低音组件、功放与布线端点美术资源。
- 增加整厅布置检查：声道缺失、左右颠倒、重复通道、超出已加载范围、碰撞与维护净空。
- 把组件登记、保存重载、专用服务器与真实客户端音频检查纳入 `verifyRelease`，并单独保留真人听感验收记录。
